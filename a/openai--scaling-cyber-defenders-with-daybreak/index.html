Daybreak으로 사이버 방어 인력의 역량 확장하기

Scaling cyber defenders with Daybreak

ChatGPT, Codex Security, 오픈소스 도구를 활용하여 위협을 조사하고, 취약점을 검증하며, 조사 결과에서 검토와 검증을 거친 수정까지 진행합니다.

Use ChatGPT, Codex Security, and open-source tools to investigate threats, validate vulnerabilities, and move from findings to reviewed, verified fixes.

보안 백로그에서 잠재적인 문제를 발견하더라도, 해당 문제가 우리 소프트웨어에 영향을 주는지 판단하고, 근거를 수집하고, 안전한 수정을 반영하는 일은 여전히 필요합니다. 코드, 알림, 취약점 보고서가 계속 쌓일수록 이 작업은 더 어려워집니다.

최근 ChatGPT, Codex Security, 오픈소스 Codex Security CLI를 활용해 이 과정을 처리할 수 있는 방법이 더 늘어났습니다. 풀 리퀘스트(pull request)를 머지하기 전에 검토하고, 저장소나 기존 취약점 백로그를 조사하며, CI에 정기적인 점검을 추가할 수 있습니다. 이러한 기능은 OpenAI Daybreak의 일부입니다. Daybreak는 승인된 방어자를 위해 모델, 보안 도구, 책임 있는 접근 방식, 보안 생태계를 하나로 통합합니다.

이전에 보고된 결과에 따르면 Codex Security Cloud는 30,000개가 넘는 코드베이스에서 3,000만 건이 넘는 커밋을 분석했습니다. 이제 시작점을 선택하고, 근거를 수집하고, 수정 사항을 검토하는 방법을 소개합니다. 이때 접근 범위는 제한하고, 중대한 결과로 이어지는 결정은 사람이 책임지도록 하는 방식을 전제로 합니다.

이러한 워크플로는 조직, 사용 사례, 위험 프로필, 데이터 처리 방식에 맞게 조정하십시오. 사용 환경에 적합한 구성, 보호 장치, 배포 방식을 선택하십시오.

ChatGPT로 조사 시작하기

이미 로그 발췌본, 보안 권고문, 사고 타임라인이 있다면 ChatGPT에서 분석을 시작하는 것이 좋습니다. 다음과 같은 작업을 시도해 볼 수 있습니다.

  • 의심스러운 로그 발췌본을 조사하고, 아직 부족한 근거가 무엇인지 파악합니다.
  • 취약점 권고문을 요약하고, 시스템에 미칠 가능성이 높은 영향을 매핑합니다.
  • 사고 타임라인을 재구성하거나 탐지 규칙의 초안을 작성합니다.
  • 새로운 기능의 위협 모델(threat model)을 준비하고, 대응 방안을 비교합니다.
  • 기술적 발견 사항을 엔지니어링 팀이나 경영진을 위한 가이드로 정리합니다.

기반이 되는 근거를 확인하고, 조직의 데이터 처리 정책을 준수하며, 어떤 조치를 취할지 직접 결정하십시오. 저장소, 풀 리퀘스트, 보안 백로그, 패치 제안을 검토해야 할 때는 Codex Security를 사용하십시오.

코드 머지 전 보안 문제 검토

Codex Security Review는 집중적인 보안 분석을 GitHub 풀 리퀘스트에 제공합니다. 따라서 이미 GitHub에서 변경 사항을 검토하고 있다면 자연스러운 시작점이 됩니다. 워크스페이스에 접근 권한이 있고 저장소가 연결되어 있으면, 다음과 같이 댓글을 남겨 검토를 요청할 수 있습니다.

@codex security review

팀의 워크플로에 맞는다면 풀 리퀘스트가 열릴 때, 푸시할 때마다, 또는 기존 Codex 코드 리뷰가 실행될 때 자동 검토를 구성할 수 있습니다. 저장소의 위협 모델이나 기타 보안 가이드는 이 과정에서 유용한 컨텍스트가 됩니다. 검토 시 애플리케이션의 자산, 신뢰 경계(trust boundary), 가정을 함께 고려할 수 있기 때문입니다.

Codex는 풀 리퀘스트의 diff와 관련된 저장소 컨텍스트를 고려합니다. 연결된 Codex 작업의 Security Report에는 심각도, 뒷받침하는 근거, 공격 경로, 검증 세부 정보, 해결 가이드가 담겨 있습니다. 보고 임계값을 확인하십시오. GitHub에 게시된 발견 사항은 해당 풀 리퀘스트의 공개 범위를 그대로 따릅니다.

Codex Security Review는 ChatGPT Enterprise, Business, Edu, Pro 계정에서 사용할 수 있습니다.

Codex Security로 저장소 조사

풀 리퀘스트 하나보다 더 넓은 범위를 다뤄야 한다면, Codex Security 플러그인으로 전체 저장소, 특정 컴포넌트, 브랜치, 커밋, 로컬 변경 사항을 평가할 수 있습니다. 첫 평가나 정기 검토에는 표준 스캔으로 시작하는 것이 좋습니다. 핵심 시스템이나 범위가 지정된 디렉터리처럼, 더 넓고 반복적인 분석에 시간과 컴퓨팅 자원을 들일 가치가 있는 경우에는 심층 스캔이 더 적합합니다.

Security workbench는 스캔, 발견 사항, 저장소를 Codex 데스크톱 환경에서 한곳에 모아 보여 줍니다. 발견 사항을 수락하기 전에 소스 근거, 심각도, 신뢰도, 공격 경로, 커버리지를 확인하십시오. 여러 실행 결과 간에 발견 사항을 비교할 수도 있고, 수락한 발견 사항을 패치 제안 단계로 진행할 수도 있습니다.

최근 workbench 업데이트에서는 스캔 단계, 검토한 파일, 활성 워커, 경과 시간, 측정된 토큰 사용량을 실시간으로 확인할 수 있습니다. 중단된 심층 스캔은 이미 완료한 작업을 반복하지 않고 이어서 진행할 수 있으며, 재사용 가능한 요약을 활용해 오버헤드를 줄입니다.

중요 저장소에 대한 지속적인 검토

저장소에 지속적인 관리가 필요하다면 플러그인 마켓플레이스에서 Daybreak Defense Factory (Preview)를 설치하고 GitHub 저장소를 연결하십시오. 한 번만 실행하는 스캔에는 Repository를, 지속적인 모니터링에는 Commit changes를 선택합니다. Codex 클라우드 환경을 선택한 뒤, 플러그인에서 스캔 진행 상황과 발견 사항을 검토하십시오.

가능한 경우 문제일 가능성이 높은 항목은 격리된 환경에서 검증합니다. 코드 발췌본, 호출 경로, 재현 출력, 해결 가이드를 검토하십시오. 아키텍처와 우선순위가 바뀔 때마다 위협 모델을 최신 상태로 유지하고, 풀 리퀘스트를 열기 전에 제안된 패치를 점검하십시오.

Daybreak Defense Factory는 리서치 프리뷰로 제공됩니다. 규모가 큰 저장소는 스캔에 몇 시간이 걸릴 수 있습니다. 커밋 모니터링을 활성화하면 Codex가 새로운 커밋을 계속 검토하며, 저장소의 Monitoring settings에서 히스토리 범위와 위협 모델을 변경할 수 있습니다.

기존 알림을 실행 가능한 큐로 전환

조사해야 할 발견 사항(finding)은 이미 충분히 많을 수 있습니다. 팀에 정적 분석 결과, 의존성 알림, 버그 바운티 보고서, 보안 권고문, 티켓이 있다면 새로운 스캔을 시작하지 않고도 현재 저장소를 기준으로 백로그를 선별(triage)할 수 있습니다.

Codex Security는 SARIF 보고서, GitHub 코드 스캐닝 및 Dependabot 발견 사항, 보안 권고문, Jira 또는 Linear 티켓, 그 밖의 취약점 보고서를 다룰 수 있습니다. 각 주장을 검토하고, 관련 입력과 코드 경로를 추적하며, 기존 통제 수단을 확인합니다. 그런 다음 증거가 조치를 뒷받침하는지, 해당 이슈가 적용 대상이 아닌 것으로 보이는지, 추가 검토가 필요한지를 설명합니다.

이러한 증거는 실제로 운영 중인 소프트웨어에 영향을 주는 이슈에 집중하는 데 도움이 됩니다. 기존 스캐너는 계속 활용하시길 권합니다. Codex Security는 결정론적 스캐닝을 보완하여 저장소에 특화된 조사를 수행하고, 필요한 경우 추가 검증을 제공합니다.

신뢰할 만한 발견 사항에서 검증된 수정까지

발견 사항이 신뢰할 만해 보인다면, 다음 질문은 안전하게 수정할 수 있는지입니다. 수용된 발견 사항에 대해서는 Codex Security에 수정안 준비를 요청할 수 있습니다. 안전하고 실용적인 범위에서 이슈를 재현하고, 변경 범위를 좁힌 패치를 생성하며, 해당 변경이 원래의 문제를 해결한다는 증거를 제공합니다.

가능한 경우 이 워크플로는 수정 전에는 실패하고 수정 후에는 통과하는 회귀 테스트를 추가합니다. 신뢰할 수 있는 테스트를 안전하게 만들 수 없다면, 검증되지 않은 부분이 무엇인지 기록합니다.

변경 사항을 적용할지 결정하는 권한은 여전히 엔지니어에게 있습니다. 발견 사항과 제안된 diff를 살펴보고, 적용 여부를 결정한 뒤, 결과를 검증하십시오. 또한 발견 사항과 보고서를 내보내거나 명시적인 승인을 거쳐 기존 이슈 관리 워크플로로 전달할 수 있습니다.

기존 도구에 보안 점검 통합

터미널, CI 파이프라인 또는 사내 도구에서 작업하고 싶다면, 오픈 소스 Codex Security CLI와 TypeScript SDK가 이러한 워크플로를 지원합니다. @openai/codex-security 패키지는 공개되어 있지만, 스캔을 실행하려면 Codex Security 접근 권한이 필요합니다.

처음 실행할 때는 CLI 사전 요구 사항과 로그인 절차를 따른 다음, 본인이 소유했거나 평가 권한이 있는 저장소에서 스캔을 시작하십시오.

npx @openai/codex-security login
npx @openai/codex-security scan .

스캔하기 전에 로컬 스캔 권한을 검토하십시오. 로컬 스캔은 운영 체제 권한으로 실행되며 승인을 위해 중단되지 않습니다. 관련 없는 자격 증명은 환경에서 제거하고, 결과는 비공개 위치에 보관하십시오. 보고서에는 소스 코드 발췌와 취약점 세부 정보가 포함될 수 있습니다.

로컬 워크플로가 유용하다고 판단되면 GitHub Actions 또는 GitLab CI/CD 점검으로 반복 실행이 가능하도록 만들 수 있습니다. 풀 리퀘스트나 머지 리퀘스트를 검토하고, SARIF를 내보내고, 보안 증거를 보존하며, 발견 사항이 선택한 심각도 임계값에 도달하면 선택적으로 점검을 실패 처리할 수 있습니다. 자체 애플리케이션을 개발 중이라면 TypeScript SDK를 통해 스캐닝, 진행 상황 보고, 취소, 비용 제어 기능을 사용할 수 있습니다.

여러 저장소와 대규모 코드베이스 스캔

동일한 검토를 여러 저장소에 걸쳐 수행해야 한다면, CLI의 대량 스캔 워크플로가 유용한 다음 단계입니다. 권한이 부여된 GitHub 계정이나 조직에서 저장소를 찾아내거나, 저장소 URL 또는 로컬 경로, 고정된 리비전, 선택적 범위, 대상별 표준 또는 심층 스캔 모드를 담은 CSV 인벤토리를 준비할 수 있습니다.

인벤토리를 준비한 후에는 저장소 외부의 비공개 출력 디렉터리를 지정하여 캠페인을 실행하십시오.

npx @openai/codex-security bulk-scan repositories.csv \
  --output-dir /path/outside/repositories/security-portfolio \
  --workers 4 --max-attempts 3

캠페인은 저장소별로 진행 상황과 결과를 따로 보존합니다. 중단된 작업을 재개하고, 동시성과 재시도를 조정하며, 공통 아키텍처 문서나 보안 정책을 제공할 수 있고, 발견 사항, 커버리지, 이식 가능한 SARIF 결과를 보관할 수 있습니다. 지원되는 모델, 추론 강도, 스캔 깊이, 예상 비용 한도를 통해 각 대상에 어느 정도의 분석이 적절한지 선택할 수 있습니다. 예상 비용 한도는 지출 상한이 아니라 추정치로 취급하십시오.

대규모 모노레포의 경우, 첫 스캔은 담당 서비스, 패키지 또는 그 밖의 의미 있는 보안 경계로 범위를 좁히길 권합니다. 표준 스캔으로 시작한 다음, 민감한 서비스나 복잡한 컴포넌트에 심층 스캔을 선별적으로 적용하십시오. 연결된 GitHub 저장소에 대해서는 Daybreak Defense Factory가 선택한 커밋 이력 구간을 검토하고, 이후 새로 추가되는 커밋도 계속 검토할 수 있습니다.

최초 캠페인을 기준선(baseline)으로 활용하십시오. 위협 모델을 갱신하고, 기존 시스템에서 발견 사항을 추적하며, 검토를 거친 수정을 검증하여 이 과정을 반복 가능하게 만드십시오.

이미 사용 중인 보안 생태계와의 연계

Codex Security는 기존 스캐너, 취약점 관리 시스템, 이슈 트래커, 서비스 제공업체, 오픈 소스 프로젝트와 함께 동작합니다. 기존 발견 사항을 가져오고, 이식 가능한 결과를 내보내며, 검토를 마친 이슈를 해당 워크플로로 다시 전달할 수 있습니다.

OpenAI Daybreak를 통해 저희는 보안 조직, 연구자, 오픈 소스 메인테이너, 파트너와도 협력하여 모델 지원 방어를 더 많은 도구와 서비스에서 이용할 수 있도록 하고 있습니다. 고급 사이버 역량에 대한 접근은 승인된 사용자가 허가된 작업을 수행하는 경우로 제한되며, 활동 유형에 맞는 안전장치가 적용됩니다.

작업에 맞는 접근 권한과 안전장치 적용

대부분의 방어 작업은 범용 모델과 Codex Security로 시작할 수 있습니다. 승인된 방어자를 위해 Daybreak Blue는 취약점 분류(triage), 악성코드 분석, 탐지 엔지니어링, 보안 조사, 패치 검증 등 승인된 작업을 지원합니다. Daybreak Red는 고급 취약점 연구, 통제된 익스플로잇 검증, 레드팀 활동 등 더 제한된 범위의 전문적이고 승인된 활동을 위한 서비스입니다. 이를 사용하려면 별도의 승인과 안전장치가 필요합니다.

최신 모델 및 Trusted Access 가이드를 참고하여 적합한 서비스를 선택하고, 사용자의 신원, 워크스페이스 또는 API 조직, 모델, 제품 인터페이스가 승인되었는지 확인하십시오. 접근 권한이 승인되었다고 해서 사용자의 환경이 자동으로 구성되는 것은 아닙니다. 대상이 되는 시스템과 작업의 범위를 정의하고, 필요한 경우 최소 권한 설정과 격리된 실행 환경을 사용하며, 중요한 결정에는 사람의 검토를 유지하십시오.

어떤 워크플로를 사용하든, 위험이 실제로 존재하는지 확인하고, 증거를 검토하고, 제안된 변경 사항을 검토한 뒤, 수정이 올바른지 검증하십시오.

When you find a possible issue in a security backlog, you still need to determine whether it affects your software, gather evidence, and land a safe fix. That gets harder as code, alerts, and vulnerability reports keep coming in.

We’ve recently added more ways to work through that process with ChatGPT, Codex Security, and the open-source Codex Security CLI. You can review a pull request before it merges, investigate a repository or an existing vulnerability backlog, and add recurring checks to CI. These capabilities are part of OpenAI Daybreak, which brings together models, security tools, responsible access, and the security ecosystem for approved defenders.

In previously reported results, Codex Security Cloud had analyzed more than 30 million commits across more than 30,000 codebases. Here’s how I’d choose a starting point, gather evidence, and review fixes while keeping access scoped and people responsible for consequential decisions.

Adapt these workflows to your organization, use case, risk profile, and data-handling practices. Choose the configuration, safeguards, and deployment appropriate for your environment.

Start with an investigation in ChatGPT

If you already have a log excerpt, an advisory, or an incident timeline, ChatGPT is a useful place to start reasoning through it. A few things to try:

  • Investigate a suspicious log excerpt and identify what evidence is still missing.
  • Summarize a vulnerability advisory and map its likely impact on your systems.
  • Reconstruct an incident timeline or draft a detection rule.
  • Prepare a threat model for a new feature and compare remediation options.
  • Turn a technical finding into guidance for engineering or leadership.

Check the underlying evidence, follow your organization’s data-handling policies, and decide what actions to take. Use Codex Security when you need to examine a repository, pull request, security backlog, or proposed patch.

Review security issues before code is merged

Codex Security Review brings focused security analysis into GitHub pull requests, so it’s a natural starting point when you’re already reviewing a change there. Once your workspace has access and a connected repository, you can request a review by commenting:

@codex security review

If that fits your team’s workflow, configure automatic reviews when a pull request opens, after every push, or whenever an existing Codex code review runs. A repository threat model or other security guidance is useful context here: it helps the review account for your application’s assets, trust boundaries, and assumptions.

Codex considers the pull-request diff and relevant repository context. The associated Codex task’s Security Report has severity, supporting evidence, attack paths, validation details, and remediation guidance. Check the reporting threshold: findings posted to GitHub inherit the pull request’s visibility.

Codex Security Review is available to ChatGPT Enterprise, Business, Edu, and Pro accounts.

Investigate a repository with Codex Security

When the question is broader than one pull request, the Codex Security plugin can assess an entire repository, a component, a branch, a commit, or local changes. For a first assessment or routine review, I’d start with a standard scan. A deep scan makes more sense for a critical system or scoped directory where broader, repeated analysis justifies more time and compute.

The Security workbench brings scans, findings, and repositories together in the Codex desktop experience. Before accepting a finding, look at its source evidence, severity, confidence, attack paths, and coverage. You can also compare findings across runs and move an accepted finding toward a proposed patch.

Recent workbench updates show live scan phases, reviewed files, active workers, elapsed time, and measured token usage. Interrupted deep scans can resume without repeating completed work, and reusable summaries reduce overhead.

Keep important repositories under continuous review

If a repository needs ongoing attention, install Daybreak Defense Factory (Preview) from the plugin marketplace and connect your GitHub repository. Choose Repository for a scan that runs once, or Commit changes for ongoing monitoring. Select a Codex cloud environment, then review scan progress and findings in the plugin.

Where practical, likely issues are validated in an isolated environment. Review the code excerpts, call paths, reproduction output, and remediation guidance. Keep the threat model up to date as your architecture and priorities change, and inspect suggested patches before opening a pull request.

Daybreak Defense Factory is available in research preview. A scan may take several hours for a larger repository. With commit monitoring enabled, Codex continues to review new commits; you can change the history window and threat model in the repository’s Monitoring settings.

Turn existing alerts into an actionable queue

You may already have plenty of findings to investigate. If your team has static-analysis results, dependency alerts, bug-bounty reports, advisories, or tickets, you can triage that backlog against the current repository without starting another scan.

Codex Security can work with SARIF reports, GitHub code-scanning and Dependabot findings, security advisories, Jira or Linear tickets, and other vulnerability reports. It examines each claim, traces relevant inputs and code paths, checks existing controls, and explains whether the evidence supports action, suggests the issue is not applicable, or requires further review.

That evidence helps you focus on issues that affect the software you actually run. I’d keep the established scanners in the picture: Codex Security complements deterministic scanning with repository-specific investigation and additional validation where appropriate.

Move from a credible finding to a verified fix

Once a finding looks credible, the next question is whether you can fix it safely. For an accepted finding, ask Codex Security to prepare a fix. Where safe and practical, it can reproduce the issue, generate a focused patch, and provide evidence that the change addresses the original problem.

When feasible, the workflow adds a regression test that fails before the fix and passes afterward. If a reliable test can’t be created safely, it records what remains unverified.

The decision to apply the change still belongs to an engineer. Inspect the finding and proposed diff, decide whether to apply it, and verify the result. You can also export findings and reports or route them into existing issue-management workflows with explicit approval.

Build security checks into existing tools

If you’d rather work from a terminal, a CI pipeline, or an internal tool, the open-source Codex Security CLI and TypeScript SDK support those workflows. The @openai/codex-security package is public, but running scans requires Codex Security access.

For a first run, follow the CLI prerequisites and sign-in steps, then start a scan from a repository you own or have permission to assess:

npx @openai/codex-security login
npx @openai/codex-security scan .

Before scanning, review the local scan permissions. Local scans use your operating-system permissions and don’t pause for approval. Remove unrelated credentials from the environment, and keep results in a private location: reports can contain source excerpts and vulnerability details.

Once the local workflow is useful, you can make it repeatable with GitHub Actions or GitLab CI/CD checks. You can review pull requests or merge requests, export SARIF, retain security evidence, and optionally fail a check when findings meet a selected severity threshold. If you’re building your own application, the TypeScript SDK exposes scanning, progress reporting, cancellation, and cost controls.

Scan multiple repositories and large codebases

When the same review needs to cover a repository portfolio, the CLI’s bulk-scanning workflow is a useful next step. You can discover repositories from an authorized GitHub account or organization, or prepare a CSV inventory with repository URLs or local paths, pinned revisions, optional scopes, and a standard or deep scan mode for each target.

After preparing the inventory, run a campaign with a private output directory outside the repositories:

npx @openai/codex-security bulk-scan repositories.csv \
  --output-dir /path/outside/repositories/security-portfolio \
  --workers 4 --max-attempts 3

Campaigns preserve progress and results separately for each repository. You can resume interrupted work, tune concurrency and retries, provide shared architecture documents or security policies, and retain findings, coverage, and portable SARIF results. Supported models, reasoning effort, scan depth, and estimated cost limits let you choose how much analysis each target warrants. Treat estimated cost limits as estimates, not hard spending caps.

For a large monorepo, I’d scope the first scan to an owned service, package, or another meaningful security boundary. Start with a standard scan, then apply deep scans selectively to sensitive services or complex components. For connected GitHub repositories, Daybreak Defense Factory can review a selected commit-history window and continue reviewing new commits.

Use the initial campaign as a baseline. Update threat models, track findings in your existing systems, and verify reviewed fixes to make the process repeatable.

Work with the security ecosystem you already use

Codex Security works alongside existing scanners, vulnerability-management systems, issue trackers, service providers, and open-source projects. You can bring in existing findings, export portable results, and route reviewed issues back into those workflows.

Through OpenAI Daybreak, we also work with security organizations, researchers, open-source maintainers, and partners to make model-assisted defense available in more tools and services. Access to advanced cyber capabilities is limited to approved users conducting authorized work, with safeguards matched to the activity.

Match access and safeguards to the work

Most defensive work can begin with general-purpose models and Codex Security. For approved defenders, Daybreak Blue supports authorized work such as vulnerability triage, malware analysis, detection engineering, security investigations, and patch validation. Daybreak Red is intended for a narrower set of specialized, authorized activities, including advanced vulnerability research, controlled exploit validation, and red teaming. It requires separate approval and safeguards.

Use the current model and Trusted Access guidance to choose the right offering and confirm that your identity, workspace or API organization, model, and product surface are approved. Access approval doesn’t configure your environment for you. Define the systems and actions in scope, use least-privilege permissions and isolated execution where appropriate, and keep human review in place for consequential decisions.

Choose a starting point

If you’re deciding what to try first, I’d start wherever your team already has work to do:

  • Open ChatGPT for an initial investigation.
  • Install the Codex Security plugin to assess a repository or triage an existing backlog.
  • Configure Codex Security Review to check pull requests before they merge.
  • Connect a repository to Daybreak Defense Factory for ongoing analysis.
  • Explore the CLI and TypeScript SDK to add checks to existing tools.
  • Review Trusted Access for Cyber and OpenAI Daybreak for advanced, authorized work.

Whichever workflow you try, establish whether the risk is real, inspect the evidence, review the proposed change, and verify the fix.
